## Baseline and evidence

Audited stacked source: PR #45 Diagnostics Center → PR #46 complete-source audit
→ PR #47 trusted ClamAV archive → PR #48 repair rollback → PR #49
post-audit fixes. The PR #48 head was \`678e366709f3f53944971c1eacfe2d81f197505c\`,
containing **229 tracked files** (~1.92 MB). PR #49 adds additional
regression tests and this report; use the CI's latest commit-specific
\`.audit/full-source.json\` for exact current counts/hashes.

The \`full-source-audit.yml\` workflow enumerates **all tracked files** with
Git, hashes their bytes, loops over **every line of UTF-8 text**, parses
Python/JSON/YAML/TOML/XML/shell where supported, checks every PowerShell
file using a Windows PowerShell AST, and retains per-file evidence. CI
also tests Windows/Linux Python 3.11–3.13, ClamAV integration, C/C++
sanitizers, WDK native build, native C/C++ CodeQL, NSIS, Store MSIX
and hardened Nuitka where triggered. Security-linter findings are
*review leads*, not automatically vulnerabilities.

This is **not a line-by-line formal proof of semantic correctness**.
Native driver operation, real ClamD database initialization, Windows 10
UAC/SCM, crashes and AV efficacy require a real isolated Windows system.

| Priority | Component | Confirmed issue | Change and evidence |

| P1 | \`scripts/protection-engine.ps1\` | Fresh installation could replace a pre-existing root Task Scheduler FreshClam task via \`Register-ScheduledTask -Force\`. | Refuse an existing task and registry binding, remove \`-Force\`, recheck after UAC and immediately before task registration. Source-contract and Windows fixture tests. |
| P1 | \`scripts/protection-engine.ps1\` | Before-UAC installation destination checks could become stale; \`-Force\` directory creation and delayed \`createdData\` ownership marking increased the risk of touching files not created by this operation. | Repeat machine-state preflight after elevation; create roots without force; mark ownership on successful creation and harden root ACL before writing children. |

## Important existing safeguards confirmed in source

- ClamAV official archive SHA-256 and size are pinned and its extracted
  clamd/freshclam executables are byte-attested; arbitrary unsigned manual
  binaries cannot use that shortcut. Installed trust receipt is subject to
  Program Files ACL checks. *Vendor detached GPG signatures are not yet
  verified independently.*
- Windows Guard checks local ClamD ownership via SCM service account,
  process/image identity and peer connection; when the engine is unavailable
  or definitions are stale it reports degraded, not healthy.
- The update installer validates SHA-256 and a pinned Authenticode leaf
  certificate thumbprint, with checks again in the installer handoff.
- Quarantine uses per-user DPAPI, limits, cryptographic digest validation,
  exclusive restores and no-overwrite semantics.
- The storage cleaner requires original scan candidate snapshots, checks
  same-file identity before deletion, and persists verified backups before
  removing original files. **Content-only backup creation is deliberate
  after the exclusive-open fix; timestamp/ACL restoration is not guaranteed.**
- Antimalware UI runs without permanent elevation; privileged maintenance
  checks executable path/NTFS ACLs and requires explicit UAC.
- NSIS stages the application payload and supports same-volume rollback
  for known application files. It does **not** atomically restore all
  registry/service/database state after hard shutdown.

## Unresolved release blockers and follow-up audits

| Severity | Issue | Required acceptance |
| --- | --- | --- |
| P0 for standalone-AV claim | No end-user proof that the exact pinned ClamAV binaries start successfully as the protected Windows service, fetch signature databases and scan EICAR. | Real signed production distribution, isolated Win10/11 VMs, ClamD/FreshClam/Guard smoke and healthy/failed/degraded state verification. |
| P0 for pre-execution-AV claim | Guard is post-write monitoring, not a certified pre-execution blocking filter. The WDK minifilter is explicitly experimental. | Separate kernel driver threat model, safe denial semantics, fuzzing, Driver Verifier, signing, crash/reboot coverage and staged rollout. Never market pre-execution blocking without proof. |
| P1 | Full SCM/task/registry rollback after power loss or partial Windows API failure is not atomic, including new installation error cleanup. | Windows VM failure injection at each mutation step; verify foreign tasks/data and old service state are preserved. |
| P1 | User-selectable backup root/ancestor paths may be redirected (links/junctions), and per-file snapshots cannot eliminate all hostile filesystem races. | Stronger directory-handle/ACL boundary and adversarial junction tests before claiming safe unattended delete in hostile folders. |
| P1 | Unquoted legacy ClamD SCM binary paths with spaces are accepted by a compatibility path, creating ambiguity with Windows executable lookup rules. | Normalize service registration to a properly quoted executable path; reject ambiguous unquoted paths before treating SCM identity as trusted. |
| P2 | Native Windows driver CI validates build/sanitizers/source but not kernel operation on every Windows version/patch. | Driver Verifier, controlled file I/O on a real kernel, signed driver load/unload and reboot tests. |
| P2 | Heuristic diagnostic redaction can miss unusual secrets and machine-local service logs run under other users. | Protected service event collector with explicit ACL/IPC; privacy tests with adversarial input. |
| P2 | Pinning a single update publisher leaf certificate impedes seamless certificate rollover. | Explicit signed key rollover protocol without accepting arbitrary certificate updates. |
| P2 | Windows 10-era API proxy is not actual Windows 10 coverage; hosted Windows runners are primarily newer Windows Server. | Real Win10/11 desktop GUI/NSIS/UAC/SCM smoke matrix. |

## Ship/no-ship decision

**Do not merge into master or publish as fully protective antivirus based on
static analysis alone.** First require all CI workflows green on the precise
final PR commit, then complete the real-world release gates above. Test and
document every manual override or fallback. In particular, fail closed when
SCM engine identity, archive trust, service health, or rollback ownership is
uncertain.
